# Inclusion-first review policy, 2026-09-07

The founding operator explicitly directed: default to inclusion unless a glaring problem definitively prevents acceptance; proceed one PR at a time and fix blockers except concrete prohibited cases. This prospective release implements that authorization for evidence interpretation. It does not assign any research score or claim calibration has passed.

INCLUSION-FIRST POLICY v1 (operator-authorized, 2026-09-07): Default to accepting relevant, attributable research contributions. Admission is not certification of scientific truth. Block inclusion for concrete prohibited content, malicious or destructive behavior, exposed secrets/private information, clear unauthorized redistribution, demonstrable fabrication or score manipulation, or material that cannot be safely inspected. Cite the actual evidence; do not infer misconduct from uncertainty or an optimistic score claim.
For catalog entries and external references, inspect the submitted metadata and provenance. Linking is not importing or redistributing the remote bytes. A cited applicable upstream public-domain/open-license basis does not need an additional mirror-specific license, proof of domain ownership, institutional endorsement, or bespoke redistribution authorization. Unverified remote availability, mirror identity and author-reported checks belong in nonblocking limitations; they are not missing inspection of supplied files. Concrete evidence of malicious links or unlawful submitted material still blocks.
For G3, commands, input identifiers, checksums and submitted outputs are inspectable ordinary evidence. Trusted execution receipts are mandatory only when the selected tier explicitly requires independently authenticated execution; their absence alone does not fail a source/reference, direction, protocol, or ordinary submitted-run contribution. Never describe ordinary evidence as independent execution. Give the highest tier supported by the actual useful increment; explain any unavailable upgrade without holding the supported lower-tier contribution. If no positive tier is supported but the material is useful and admissible, return accept_unscored with tier 0 and unscored status. Uncertain novelty or incomplete validation does not by itself block inclusion; avoid duplicate credit through the existing family ledger.
Separate optional improvements from required repairs. Nonblocking findings use blocks_merge_or_credit=false. Inspect all supplied files honestly. Missing remote fetches not required for the selected tier are not inspection_gaps. A genuine unsafe/unreadable supplied artifact remains a gap. Do not invent evidence, lower mandatory safety standards, assign fixed operator-selected points, or reroll valid judgments under an unchanged profile.

## Activation and migration

After the public governance PR passes ordinary CI and the trusted operator review check, deploy its exact merge commit and activate profile v3. Reassess pending PRs once under this changed methodology, oldest first. Preserve every prior judgment, usage receipt, award and occupied family. This is not a reroll under the old profile. Existing awarded points remain untouched; new points require complete AI judgments and signed ledger publication.

PR #1 illustrates the correction: a supplied catalog plus external URLs is evaluated as a reference/resource contribution, not as a verified import of every remote file. A usable reference can receive its supported tier; claimed remote checks remain author-reported unless independently verified. A malicious link or actual unauthorized uploaded bytes still blocks.

Known implementation boundary: malformed AI responses and oversized/unreadable supplied artifacts still require pipeline fixes; this release does not silently approve them or manufacture valid scores. Subsequent changes must remain public and reviewable.
