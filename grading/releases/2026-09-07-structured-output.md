## Current v6 schema-constrained assessment transport

The active profile uses Claude Code's native JSON-schema output formatter. Repeated missing required fields in the earlier text-only transport prevented valid assessments and settlements. The sole permitted StructuredOutput tool serializes the assessment; research tools, shell, files, network access and project actions remain unavailable. The server still independently validates the complete schema, evidence references, admission and scoring rules. It never invents missing outcomes or fills blocking flags.

There are at most four assessment stages and one client invocation per stage, with up to four native client turns and two formatting retries per invocation (at most sixteen turns across the job). These are bounded format-completion turns, not independent scoring rerolls. Each invocation retains the 120-second runtime limit and 6,000 output-token setting; the raw output envelope is 128,000 bytes to accommodate formatter output. The controller records client sessions and actual transport bytes/runtime; those are not a claim to count provider tokens or repeated internal prompt billing. Aggregate operating ceilings and usage counters remain unchanged.

This supersedes earlier text-JSON/no-formatter/one-turn transport language. The v5 artifact limits, inclusion-first rules, qualitative tiers, immutable prior receipts and conservative fourth-stage correction guard are unchanged. Existing awards remain intact. Pending invalid assessments may be evaluated under this published new transport version; valid judgments cannot be rerolled under an unchanged profile. Calibration remains incomplete and supported official AI scores continue to be awarded. Operator-authorized pipeline repair earns no research points.
